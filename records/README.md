## 五、怎么重建

按顺序跑 `_脚本/` 下四个脚本，每步依赖上一步的产物：

```bash
python _脚本/parse_progress.py    # 原始 txt → 规范化 CSV + _stats.json
python _脚本/gen_kb.py            # → 测试进度知识库.md、明细-YYYY.md
python _脚本/gen_json.py          # → 测试进度_2024-2026.json
python _脚本/gen_rag_pack.py      # → 查询知识库/ 9 份上传件
```

站点侧再跑 `company/gongchengbu/知识库/_脚本/sync_kb.py` 把 JSON 导出成查询页数据。

## 六、用之前必须知道的五个坑

1. **合格率分母含未判定和未出结果**，所以比 `合格/(合格+不合格)` 低，别和别的口径混着报。
2. **跨年统计口径会跳**：2026 不是完整年度，且新增了 LIMS 来源。三年对比优先按测试项目切。
3. **2024 年有脏日期**：134 条预计完成时间写着 2021 年，1 条实际完成时间误填 2224 年。准时率和周期都是剔除异常后算的。
4. **报告编号不能按固定长度校验**：数字段有 7/8/9/10 位四种形态，2026 年起还多了 8 位全年份写法。检索按前缀 `GC` 匹配。
5. **裕量不足（余量小）69 单不算不合格**，是单独的隐患清单，别合并进不合格数。
