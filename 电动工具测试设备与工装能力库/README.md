# 电动工具测试设备与工装能力库

> 实验室设备、仪器与工装的能力/校准台账，支撑测试选型、校准提醒与 CNAS/CMA 评审取证。
> 最后更新：2026-11-19（首批建库）

## 一、这个库是什么

| 项 | 内容 |
|---|---|
| 设备总数 | **125 台**：118 条固定资产（机器设备 30 + 仪器仪表 88）+ 7 台外校清单独有设备 |
| 外校设备 | **19 台**（九月份通知单 `FF19008-01`），其中 **12 台**与资产表按编号关联 |
| 工装夹具 | **10 条**（独立主体，从测试用例设备字段提取的 `REQ-` 需求占位；用 `fixture_rows.xlsx` 回填正式 `FG-` 编号）|
| 编号照片 | **39 张**固定资产编号铭牌，其中 **24 台**设备编号可回连 |
| 用途 | 按编号/名称/型号查设备，看外校与照片佐证，确认能力边界与待补字段 |

## 二、目录里有什么

```
README.md                       本说明
查询.html                       离线查询页（双击即开，数据在 查询数据/）
查询数据/equipment.js           125 台设备 + 19 条外校 + 5 条工装候选
查询知识库/                     唯一一份单文件 md（供离线检索 / RAG）
  电动工具测试设备与工装能力查询知识库.md   0.03 MB
_脚本/build.py                  按 SQL 字段从两份 TSV 重建查询数据
_脚本/fixture_rows.xlsx          后续 UI/Excel 回填工装的录入表（可选，存在即优先采用）
电动工具测试设备与工装能力库.md  建库需求说明（编号规则、维护规则）
电动工具测试知识库_建表SQL.sql.sql   MySQL 建表语句（test_equipment / test_fixture，权威字段定义）
电动工具测试知识库_字段模板.xlsx      回填用 Excel 模板（含工装夹具 sheet）
```

**原始文件都还有用**：`建表SQL.sql` 是字段/值域权威（`test_equipment` 27 字段、`test_fixture` 8 字段），`字段模板.xlsx` 是回填录入表，`电动工具测试设备与工装能力库.md` 是编号与维护规则。这版数据已严格按 SQL 字段输出。

**工装是独立主体，不是设备附表**：查询页第一个 Tab 就是「工装夹具」，单文件 md 第四节是完整 `test_fixture` 表。目前 10 条 `REQ-` 编号是从 156 条测试用例的 equipment 字段提取的真实工装/台架需求（安全联锁装置、跌落试验台、砂轮爆破试验台、护罩耐久试验台、标准测试台架、夹具等），不是凭空造的实物台账；你后续用 `fixture_rows.xlsx` 或 UI 填好适用设备/产品/状态/验收日期/检查周期后，重跑 `build.py` 即自动用回填数据替换占位。

## 三、数据来源与关联键

| 来源 | 路径 | 提供字段 |
|---|---|---|
| 固定资产盘点表 | `数字化/实验室管理/原始数据/设备管理.txt`（截止 2025-08-31，163 条） | 编号、存货号、类别、部门、责任人、资产描述、规格型号、资本化日期 |
| 外部校准明细 | `数字化/实验室管理/原始数据/电动工具外部校准设备明细.txt`（19 台） | 本厂编号、设备名称、型号/量程、精度、出厂编号、制造商、通知单号 |
| 编号照片 | `数字化/实验室管理/测试照片/固定资产编号/`（39 张） | 编号佐证（铭牌），不含名称/型号 |

**关联键**：资产表的「存货号」（如 `JF1-8-032`）对应外校表的「本厂编号」。资产表的「编号」列是数字资产账号（如 `1140000008`），已存为 `assetId`，不要用它去匹配外校清单。

## 四、字段落地情况

| 字段 | 来源 | 状态 |
|---|---|---|
| 设备编号 / 名称 / 型号 | 资产表「存货号 / 资产描述 / 规格型号」；外校表补 7 台 | 125 条有值 |
| 制造商 / 精度 / 量程 / 出厂编号 | 外校表 | 12 条关联设备有值，其余待补 |
| 类别 / 存放位置 / 责任人 | 资产表「类别描述 / 部门描述 / 库存注记」 | 大部分有值，颗粒度到科室 |
| 购置日期 | 资产表「资本化日期」规范化 | 118 条有值（**近似购置日期**）|
| 设备状态 / 启用日期 | 源头无明确字段 | 统一「待核实」，不按账面数量推定 |
| 校准周期 / 上次下次校准日期 / 机构 / 证书编号 / 结论 | 仅有外校通知单号与月份 | 待补 |
| 期间核查 / 维护记录 | 外校表仅出厂编号作为维护记录线索 | 待补 |
| 工装适用设备 / 适用产品 / 检查周期 | 无独立工装台账 | 待判定 |

## 五、怎么用

1. 双击 `查询.html`，**第一个 Tab 是「工装夹具」**（主体），其次「设备台账 / 外部校准」；搜索编号/名称/型号/位置/责任人。
2. 点工装条目可看到 `fg_code / fg_name / apply_equipment / apply_product / status / accept_date / check_cycle / remark` 全部 SQL 字段。
3. 顶部 chips 按类别或状态筛选；外校设备有「外校」标记。
4. 点条目展开详情，注意「待核实 / 待补」字段不可当实测值引用。
5. 离线 RAG 用 `查询知识库/电动工具测试设备与工装能力查询知识库.md`，第四节是完整工装表。

## 六、怎么重建

```powershell
cd 知识库/电动工具测试设备与工装能力库/_脚本
python build.py
cd ..\..\_脚本
python build_query_kb_all.py
```

解释器用 `C:\Users\Administrator\AppData\Local\Programs\Python\Python314\python.exe`。源文件更新（盘点表/外校明细）后重跑即可，查询页无需改动。

## 七、与其他库的关系

- **测试方法与用例库**：用例「测试设备」写的是设备名称，待人工映射为本库设备编号。
- **测试记录知识库**：记录中可记设备编号，实现结果到设备的追溯（目前未回填）。
- **测试标准与认证知识库**：设备「适用标准条款」尚未从体系文件提取。

## 八、已知问题

- 没有独立工装台账，10 条 `REQ-` 是从用例提取的需求占位，须人工补齐适用设备/产品并改正式 `FG-` 编号。
- 校准证书编号、有效期、结论在现有资料中缺失；照片里同框的绿色计量合格证只有片段日期，未入库。
- 外校清单中 7 台不在资产盘点表内，单列为「外部校准设备」类别，不等于新增资产。
- `company/tool-test-assistant` 中没有设备/校准清单，不能作为本库数据源。
