# 电动工具测试方法与用例库

> 把实验室已形成的测试方法、大纲测试项与企标方法结构化沉淀，用于选型套用、减少漏项和判定不一致。
> 最后更新：2026-11-19（按 SQL 字段重建 + GB 3883 测试方案）

## 一、这个库是什么

| 项 | 内容 |
|---|---|
| 记录总数 | **538 条**：156 条 SQL 用例 + 324 条大纲测试项 + 35 份大纲文档 + 23 个企标/受控方法 |
| 测试方案 | **4 套 / 13 项**（`解决方案.html`）：GB 3883.1 / .201 / .203 / .206，8 步完整流程 + 不适用边界 5 条 |
| 完整用例来源 | `company/tool-test-app/src/data/tests/testData.js`（7 大类 / 15 子类，含步骤、判定、设备、注意事项） |
| 大纲项来源 | `company/tool-test-app/src/data/outlines/testOutlineData.js` 的 `flatOutlineItems`（324 条） |
| 大纲文档来源 | 同上 `testOutlineDocuments`（35 份，含页数与分类） |
| 企标方法来源 | `数字化/实验室管理/测试大纲/实验室发布企标`、`实验室批准受控测试方法` 的文件夹名（提取 QJFF / QT 编号、名称、版本、页数） |
| 用途 | 测试前查方法、按产品/测试类型找用例、与标准库/失效案例库/型号库交叉引用 |

> 数据来源是 `tool-test-app` 的 App 数据文件，**没有**现成的用例 JSON/CSV/xlsx；本库是将其导出并结构化后的离线副本。

## 二、目录里有什么

```
README.md                       本说明
查询.html                       离线查询页（双击即开，数据在 查询数据/）
查询数据/methods.js             538 条全量数据（window.KB.methods）
查询知识库/                     唯一一份单文件 md（供离线检索 / RAG）
  电动工具测试方法与用例查询知识库.md   0.21 MB
_脚本/
  _export_app_data.mjs          Node 脚本：从 tool-test-app 导出 tests/outlines 为 JSON
  _src_tests.json               导出中转（156/324/35 条原始字段）
  build.py                      生成 查询数据/methods.js（按 SQL 21 字段）
  _src_standards.json           标准清单与详情导出中转
  build_solutions.py            生成 GB 3883 方案 + 流程图页面
解决方案.html                    GB 3883 测试方案（8 步流程 + 项目表 + 不适用边界）
测试方法与用例库.md              建库需求说明（编号规则、维护规则）
电动工具测试知识库_建表SQL.sql.sql   MySQL 建表语句（test_method_case，权威字段定义）
电动工具测试知识库_字段模板.xlsx      回填用 Excel 模板（用例/设备/工装/字段说明 4 个 sheet）
```

**三个原始文件都还有用，是权威结构，不是废文件：**
- `建表SQL.sql` 定字段、类型、必填与值域；`methods.js` 的 156 条已严格按 `test_method_case` 的 **21 个业务字段**输出。
- `字段模板.xlsx` 是人工回填缺失字段的录入表，填好后按 SQL 导入 MySQL。
- `测试方法与用例库.md` 是编号与维护规则。上一版我只看它定字段、没让数据按 SQL 落字段，这版已纠正。

## 三、字段落地情况

| 字段 | 来源 | 首批状态 |
|---|---|---|
| 用例编号 | 入库时按源文件顺序生成 `TM-2026-NNN`，保留源标识 `codeSource` | 有值（**非历史正式编号**）|
| 用例名称 / 类别 / 子类 | `testData.js` 的 `name / catName / subName` | 156 条有值 |
| 适用标准 / 标准版本 | `standard`（如 `GB 4343.1-2024 §5 / CISPR 14-1`）| 156 条有值，版本需单独核对 |
| 测试目的 | `fullDesc / desc` | 156 条有值 |
| 测试设备 | `equipment[]` | 156 条有值（设备名称，未逐条挂设备库编号）|
| 测试步骤 / 判定规则 / 注意事项 | `detailedSteps / criteria / requirements / notes` | 156 条完整；大纲项多数为空 |
| 样品要求 / 环境条件 / 数据记录项 | 源头未见结构化值 | 待补（体系文件 15 份 REC 模板可提取）|
| 关联失效案例 | 失效案例库 93 条可按测试项目关联 | 未逐条回填 |
| 编制人 / 审核人 / 生效日期 / 状态 | 源文件未见用例级元数据 | 待补，`status` 暂记「在用」|

## 四、怎么用（重点：测试方案）

1. **先看 `解决方案.html`**：按 GB/T 3883.1 / .201 / .203 / .206 展示「测什么 → 完整 8 步流程 → 判定 → 设备 → 工装」，并列不适用/豁免边界。这是本库的主交付视图，不是单纯罗列用例。
2. `查询.html` 是执行层明细：Tab 切换「SQL 用例 / 大纲项 / 大纲文档 / 企标方法」，搜索框跨当前 Tab 全文匹配，点条目展开步骤与判定。
3. 离线 RAG 用 `查询知识库/电动工具测试方法与用例查询知识库.md`，内含 538 条全量字段 + 第六节 GB 3883 方案 / 流程 / 不适用边界。
4. 企标方法只有编号/名称/页数，正文是扫描页，需回 `测试大纲/` 原件。

## 五、怎么重建

```powershell
cd 知识库/电动工具测试方法与用例库/_脚本
node _export_app_data.mjs                      # 从 tool-test-app 重新导出 tests/outlines/standards
python build.py                               # 按 SQL 21 字段生成 methods.js
python build_solutions.py                     # 生成 solutions.js + 解决方案.html
cd ..\..\_脚本
python build_query_kb_all.py                  # 刷新六个库的单文件 md（含方案章节）
```

解释器用 `C:\Users\Administrator\AppData\Local\Programs\Python\Python314\python.exe`（默认 3.15 也可跑本库脚本，但六库统一生成器建议 3.14）。

## 六、与其他库的关系

- **测试标准与认证知识库**：用例「适用标准」指向标准编号，标准换版时触发用例评审。
- **测试设备与工装能力库**：用例「测试设备」应与设备编号对应；目前只有设备名称，待人工映射。
- **测试失效案例库**：按测试项目提示历史风险点；案例的原因/规避为模板推断，未经报告核实。
- **电动工具竞品型号库**：按产品类别/工具类型筛适用用例。
