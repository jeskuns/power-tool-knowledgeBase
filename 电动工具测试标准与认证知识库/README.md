### `03_全文/` 与 `04_全文OCR/` 的区别

| | `03_全文/` | `04_全文OCR/` |
|---|---|---|
| 源文件 | PDF **自带文字层**（普查 `text` / `low`） | 纯扫描图像、**没有文字层**（普查 `scanned`） |
| 怎么来 | `kb_extract.py` 用 PyMuPDF 直接 `get_text()` 抽取，不做识别 | `kb_ocr_batch.py` 逐页渲染成图 → RapidOCR 识别，约 13 秒/页 |
| 数量 | 834 篇，静态；只有新增文字层 PDF 时才补 | 1120 篇，2026-11-20 全部 OCR 完成，剩余 0 |
| 数值可信度 | **分两档**：`full`（汉字+数字都在文字层，可引用）、`MD?`（数字是矢量描边取不出来，只能定位章节） | **一律不可直接引用**，每篇开头有免责声明，只用于定位条款 |

## 六、用之前必须知道的四个坑

1. **`MD?` 的正文不能用来判数值。** 这类 PDF 汉字能取出来，但数字、单位、标准号是画上去的矢量描边，正文里直接空白。只能用来定位在哪一章，**判定必须回 PDF 原件**。
2. **OCR 正文的数值也不能直接引用。** 识别错误、表格列错位、双栏串行都可能发生，只用来定位条款；查询知识库文档已标注这一点。
3. **加密的 140 个文件任何工具都打不开**，不是脚本坏了，是亿赛通密文。
4. **版次是否作废没核过**，「状态」列只认文件名里已有的【现行】【参考】字样；`重复文件报告.md` 与 `按标准号检索.md` 对「多版本」的统计口径不同（43 / 51），人工核对时以按标准号检索的清单为准。
