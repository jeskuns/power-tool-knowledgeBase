## 一个必须逐文件确认的坑：有的文字层里没有数字

审计了 846 个有文字层的文件，**713 个是完整的**（汉字和数字、单位、标准号都在文字层里，实测每页中位 58 个数字）。

但 **91 个不是**：这类 PDF 的汉字能取出来，数字和字母是画上去的矢量描边，不在文字层里。
直提出来会变成这样——

> 对额定电流大于 **（原件这里写着 16 A）** 的设备在低压供电系统中产生的电压波动和闪烁的限制

条款号、试验电压、温升限值、引用标准号全成空白，这种 MD 只能用来定位在哪一章，**数值判定必须回 PDF 原件**。
数字缺失集中在 `标准化管理`（55 个）和 `EMC标准`（7 个）；**`安全标准` 241 个全部完整，你的主力没有这个问题。**

逐文件标注在 `_脚本/data/text_quality.json`（`full` / `weak` / `nodigit`，判据是每页数字的中位数），目录表的「可读性」列也直接写了出来。

## 怎么用

- **`总目录.md`** — 全部文件一张表，按目录排序。「全文」列有 `MD` 链接的直接点开就是可复制检索的正文，`—` 表示还没转或转不出。Ctrl+F 搜标准号、关键词。
- **`按标准号检索.md`** — 同一个标准的多个副本、多个版本并排，判版本时用这个。
- **`分类/`** — 每个大类一个文件，手机上按类浏览。
- **`加密件清单.md`** — 交给 IT 申请解密的清单，含 GB 3883.1、IEC 60745 全套。
- **`需OCR清单.md`** — 只有图像没有文字层的，转 MD 必须 OCR，按需再做。
- **`../全文/`** — 已转出的正文，跨标准搜关键词（泄漏电流、温升、灼热丝…）直接在这个目录里 grep。
- **`../04_全文OCR/`** — 扫描版 OCR 出来的正文，总目录「全文」列的 `OCR全文` 链接指向这里；识别值只用于定位，**数值判定必须回 PDF 原件**。
- **`../卡片/`** — 已提炼的判定卡：`00-交叉引用索引.md` 是总入口（条款号对照、限值速查、卡片定位），`01-16` 按试验项目，`P01-P08` 按产品。
- **`../安规标准知识库.html`** — 手机和离线阅读用的单文件版，卡片全量内嵌，可搜索。

## 已知限制

1. 「状态」列来自文件名里已有的【现行】【参考】标记，只有标了的才有；**版次是否作废仍需到官方平台核对**。
2. 「可读性=扫描版」的文件，只有「全文」列出现 `OCR全文` 链接的才有正文；其余检索不到内容，只能靠目录名。OCR 正文的数值可能有误（识别、列错位），只用来定位条款。
3. 「加密待解密」的文件是亿赛通 E-SafeNet 密文，任何工具都读不了，必须先解密。
